# 配置与边界

## 配置工程

索引器读取工程根的 `ui-index.json`；可用 `--profile` 指定工程根内的其他配置文件。以 `assets/tz956e-ui-index.json` 为结构示例，填入实际文件路径与实测尺寸。路径相对于工程根。

| 字段 | 来源与用途 |
| --- | --- |
| `source_dir` | 源码/资源 `.qrc` 所在目录 |
| `entry` / `common` | 入口 QML / 数值常量 JS |
| `viewport` | 入口内负责画面旋转与尺寸的控件 ID |
| `page_container` / `bar_instance` | 页面 Loader / 公共按键栏实例 ID |
| `roles.base` / `bar` / `status` | 页面基类、按键栏、顶部状态栏 QML 文件 |
| `controls` | 按键类型到组件定义文件的映射 |
| `binding_sources` | 需要随索引核对的 C++ 等绑定来源，例如设置屏幕方向的入口 |
| `framebuffer_size` | 查询设备得到的原始 framebuffer 宽高，不用旋转后的预览尺寸 |
| `program.version` / `sha256` | 与参考截图对应的已编译程序版本和 SHA256 |
| `pages.<别名>.source` / `uri` | 页面源码和导航资源 URI |
| `pages.<别名>.form` | 可选：容器页面内实际继承 FormBase 的页面文件 |
| `pages.<别名>.title` | 查询结果中使用的页面名称 |
| `pages.<别名>.captures` | 至少两张同版本、不同时间的原始 framebuffer PNG |

角色与控件 ID 用 CodeGraph 定位后填写。配置中没有按钮坐标字段。控件区域由源码计算；图片用于确认位置、生成控件检查和目标页检查特征。

索引不会启动程序来执行 QML/JavaScript。它解析声明、父子关系和函数体，并对受支持的数值表达式求值。复杂绑定需要运行时信息时，保留 `unresolved` 原因供适配。

## 已实现的布局子集

- 已校准的居中根视口，0/90/180/270 度旋转，尺寸与 framebuffer 相同或宽高互换。
- 公共状态栏、页面与底部按键栏按源码的上下锚定关系排列；尺寸相加须符合画布。
- 数值常量、加减乘除、父项/兄弟尺寸、直接位置，以及目前使用的单边/中心锚定。
- 左到右 Row、指定列数与统一 spacing 的 Grid，静态尺寸按键。
- 已确认的 FormBase 按键释放信号连接、页面覆盖的回调及每页 `setButtonPic` 释放图片。
- 组件内一个填满父项的 MouseArea，释放时调用 `onBtnRelease()`；当前适配 Control_Btn/Control_Btn6 这一类结构。按下回调包含额外行为时，自动导航保留为未解析。
- 导航函数体须是单个 `iMainWindow.showpage(...)`，参数为字面量；条件、动态函数参数或额外语句不进入自动路线。

原始 framebuffer 坐标与旋转后预览坐标分开保存，驱动触摸范围仍由设备端执行器查询。当前图像校准只接受资源原生尺寸显示，通过 alpha 与画面背景合成检查资源位置；缩放后的图像先保留为未解析。

视口、页面 Wrapper、多页 SwipeView、隐藏/启用条件、运行时变换或布局规则不符合上述条件时，先适配并单步验证。此版本尚未提供运行时控件信息导出，也未实现完整 QML、Widgets .ui 或任意模型/布局求解。

## 状态与失效

- `image_confirmed`：静态点击区域在画布内，释放图片与该页参考截图匹配，具备控件检查特征。
- `unresolved`：保存原因；不进入自动导航。
- `live_verification`：某个确定计划、程序指纹和设备轮次的实测记录。不会把其他同类按钮自动标为已点击通过。

索引按内容哈希核对已读取的源码、资源、配置、参考截图以及索引器版本，并检查 `.qrc` 文件清单。文本哈希按 UTF-8、统一换行计算，图片按原始字节计算。已跟踪输入变化时，旧坐标查询和计划生成会被拦截。

使用本机镜像时，先同步本轮配置覆盖的源码、资源和截图，再执行 `build/status`。`fresh` 仅表示本机已跟踪输入未变化，工具不会主动连接 Linux 检查远端；执行前的远端 `source_sha256` 核对负责跨机器一致性。

无变化时整体复用已生成索引；有变化时重建本配置覆盖的页面。这不是全工程逐控件增量计算，也不自动发现未配置的全部页面。新增测试页面时先补充源码角色和两张截图，再重新建索引。

## 页面识别与执行

目标页特征由同页截图的稳定像素生成，并排除其他页面相同位置的特征与黑色背景。控件检查来自资源所在区域的稳定可见像素。默认页面特征 256 点、控件特征最多 128 点，颜色容差 20、匹配率 97%，页面连续两次匹配后继续。它们属于这组截图的识别模板，布局、主题、语言或运行状态变化后重新核对。

计划包含 `program`、`source_sha256`、`generation_id` 和 `plan_id`，以及每步的 `control/from/target/click/guard`。执行前：

1. 确认源码、资源、截图与已编译程序对应；编译后有源码变化时先解决版本对应关系。
2. 在部署/监督任务中核对实际运行 ELF 的 SHA256 与 `program.sha256`，对照 `source_sha256` 检查源码/资源快照。单独执行触控脚本不完成这些程序身份检查。
3. 将原样生成的计划交给支持 `guard` 的批量执行器。每步先检查控件可见特征，失败时保存 `guard-failed-NN.png` 并停止；目标页检查、整体超时及程序/挂载恢复按现有测试流程执行。
4. 截图目视核对后，再记录对应业务测试项。参考图片匹配不能代替 CAN 报文或数值验收。

## `record` 结果契约

`--result` 是设备监督任务保存的 JSON，至少包括：

| 字段 | 验证内容 |
| --- | --- |
| `passed` | 监督任务确认本轮测试与约定收尾已完成 |
| `stage` / 可选 `boot_id` | 设备上的本轮证据目录 / 启动轮次 |
| `test_sha256` | 已核对的实跑程序 SHA256 |
| `experiment.indexed.passed` / `plan_id` | 此计划已执行通过，ID 与原始计划一致 |
| `experiment.indexed.steps` | 顺序对应全部步骤，含 `name/score/guard_score` |

`record` 同时检查计划内容哈希、索引 generation、程序指纹、步骤身份和匹配率。其他监督脚本可把真实记录转换成此结构；缺失的运行证据保留未验证状态。重建索引后原 generation 的结果不能回填。
