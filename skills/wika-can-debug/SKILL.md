# WIKA CAN 通讯调试

先查清当前程序如何接收和发送 CAN，再选择测试入口。无外部节点时可先做显示器本机模拟；有 CAN 盒时可补充物理收发。按用户要求的范围判定完成，不把某一层通过扩大为整车验收。

## 1. 确认实际程序和配置

- 复用当前会话可用的远程连接；设备连接、程序启停可调用 [wika-displayer-online](../wika-displayer-online/SKILL.md)。记录服务 MainPID、`/proc/<pid>/exe` 及哈希，确认运行的是当前要测的程序。
- 使用工程的 CodeGraph 定位启动、读写、发送及消息分发实现，再读命中的文件。核对 `RunInDevice` 等编译分支，避免将非实机封装的固定返回值当作真实 SDK 结果。
- 从源码和协议取得通道、节点、波特率、标准/扩展帧、COB-ID、变量索引、字节序及换算。核对程序实际加载的 EDS/.h/.var 与当前 `BIN`。涉及修改配置时使用 [wika-eds-edit](../wika-eds-edit/SKILL.md)。
- 切换接口或停止程序前保存接口配置、当前运行服务及原文件哈希；恢复流程和测试超时放在显示器本机监督进程中，避免远程连接断开后遗留回环或停止的界面。

## 2. 选择测试方法

| 目标 / 条件 | 方法 | 能证明什么 |
| --- | --- | --- |
| 无外部 CAN 节点，控制器支持内部回环 | 本机 `PF_CAN/CAN_RAW` 脚本 + 控制器 `LOOPBACK` | 真实 SDK 的帧接收、EDS 映射与 PDO 组帧/发送路径；已在 ICM7100 验证。 |
| 内核支持 vcan，SDK/程序可绑定该虚拟接口 | 虚拟 CAN 网络中运行发送端与接收端 | 软件帧链路；先确认绑定和初始化兼容，当前案例的 vcan 不受支持。 |
| 只需检查某个页面的数据处理 | 依据实际实现注入对象值或本地消息 | 上层逻辑；跳过的 EDS/CAN 层单独标注。当前案例只查明相关 API，未验收直接消息注入。 |
| 需要检查设备端口或真实总线 | 实体 CAN 盒 / 另一节点与显示器互发 | 物理收发；需要硬件后端的实际 RX 记录。 |

无外设模拟或需要核对 SDK/Qt 接收链路时，读 [ICM7100 本机模拟方法与实测案例](references/icm7100-loopback.md)。该参考包含两层消息路径、接口回环命令、脚本入口及适用范围。

## 3. 验证接收和发送

1. 记录真实 SDK 的 baud/start/帧模式/start_node 返回值、加载配置的路径和哈希。调用参数及 ctypes 签名以当前 SDK 头文件为准。
2. **接收**：从选定的帧入口发送两组不同载荷，读取 EDS 映射变量和对象，核对全部字节与换算；改过 ID 时加旧 ID 对照。对照帧先确认确实到达接收接口，再判断是否更新映射。
3. **发送**：写对应发送变量并触发原程序的发送函数或 SDK `send_pdo`，记录返回值和接收端看到的 ID、帧类型、DLC、完整数据。
4. **界面**：如验收包含页面，继续核对 SDK 本地消息、监视变量注册、`OnCanRecv` 或当前工程等效回调，以及页面值、状态和截图。独立 SDK 探针通过不替代这一步。
5. 将发送请求、发送 API 成功、本机回环和外部接收分别记录。实体 CAN 盒的 `tx` 回显或仅有累计计数，不能单独作为显示器物理发送的证明。

### 外部 CAN 盒测试

使用工具当前配置的实体硬件后端、通道及波特率；可复用已有 CanSimTool。接收测试由 CAN 盒发帧，读取显示器 SDK 值；发送测试由显示器发帧，在 CAN 盒的 **rx** 日志核对数据。改变载荷重测，防止误用旧帧。完整接收/发送示例还见 [wika-eds-edit 的实机收发验收](../wika-eds-edit/SKILL.md#实机收发验收)。

## 4. 定位断点

| 现象 | 下一步检查 |
| --- | --- |
| 初始化失败 | 当前启用通道、实际 EDS 路径/三件套、SDK ABI 与参数、接口状态和程序占用。 |
| 原始帧可见，SDK 值不变 | ID/帧类型、EDS 映射与数据宽度、变量序号、SDK 模式及原始帧来源。 |
| SDK 值正确，页面不变 | 本地消息接收、监视变量注册、数据换算、当前页面回调及初始化。 |
| 发送 API 成功，但接收端无帧 | 编译分支、真实发送路径、接口模式/错误、CAN 盒实际后端和过滤条件；再检查物理链路。 |
| ERROR-PASSIVE / BUS-OFF | 结合配置、错误计数和报文分析，不只凭接口状态确定原因。接口重置后的正常状态也不单独证明原故障已解决。 |

## 5. 恢复和记录

停止临时脚本，恢复原接口模式、位时序、队列及原运行服务；读取恢复后的状态和原文件哈希。正式部署或配置更新只按用户当前授权执行。

报告写清：运行程序/配置、选择的测试方法、SDK 返回与接收值、原始帧、界面验收结果及恢复结果。将结论分别标为“本机模拟通过”“物理总线通过”“界面通过”或相应未测项。使用当前工程真实协议作为正式配置，案例 ID 只用于独立试验。

需要将数值/帧断言、结果回填和回归选择接入开发流程时，读 [测试用例与证据](../wika-dev-flow/references/test-evidence.md)。按真实观测填入 SDK 值、帧来源/方向、完整载荷与本轮时间窗；历史记录只作回放，不补造时间或放大为本轮物理/页面验收。
